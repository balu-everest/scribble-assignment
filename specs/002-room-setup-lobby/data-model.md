# Data Model: Room Setup & Lobby

## Entities

### Room

| Field | Type | Description | Constraints |
|-------|------|-------------|-------------|
| `code` | `string` | Unique room identifier | 6-char uppercase alphanumeric, case-insensitive on input, stored uppercase |
| `status` | `"lobby"` | Current room phase | Only `"lobby"` for this feature |
| `hostId` | `string` | Participant ID of the host | References a Participant in `participants[]` |
| `participants` | `Participant[]` | All players in the room | Max ~10 (no hard limit yet); names unique case-insensitively |
| `createdAt` | `string` (ISO 8601) | Room creation timestamp | Set once on creation |
| `updatedAt` | `string` (ISO 8601) | Last modification timestamp | Updated on every state change |

### Participant

| Field | Type | Description | Constraints |
|-------|------|-------------|-------------|
| `id` | `string` (UUIDv4) | Unique participant identifier | Generated by server via `randomUUID()` |
| `name` | `string` | Display name | Trimmed, 1–20 chars, unique within room (case-insensitive) |
| `joinedAt` | `string` (ISO 8601) | Join timestamp | Used for host promotion ordering |

### RoomSnapshot (API response shape — not stored)

| Field | Type | Description |
|-------|------|-------------|
| `code` | `string` | Room code |
| `status` | `"lobby"` | Room phase |
| `participants` | `Participant[]` | Participant list |
| `hostId` | `string` | Host participant ID |
| `availableWords` | `string[]` | Word list (static seed) |
| `roles` | `string[]` | Role list (static seed) |

## Validation Rules

| Input | Rule | Error Message |
|-------|------|---------------|
| `playerName` | Trimmed, length 1–20 | "Name cannot be empty" / "Name must be 20 characters or less" |
| `playerName` | No duplicate in room (case-insensitive) | "That name is already taken" |
| `roomCode` (join) | Trimmed, non-empty after trim | "Room code cannot be empty" |
| `roomCode` (join) | Must match existing room | "Room not found" |
| `roomCode` (join/params) | Case-insensitive matched | Auto-uppercased before lookup |

## State Transitions

```
Room Created (hostId set to creator)
  │
  ▼
Player Joins (participant added, updatedAt bumped)
  │
  ▼
Player Leaves (participant removed, host transferred if needed)
  │
  ▼
All Players Leave → Room orphaned (no explicit deletion)
  │
  ▼
[Future] Game Started → status transitions to "playing"
```

## Host Promotion Rules

1. When host disconnects or leaves, the remaining participant with the **earliest `joinedAt`** becomes the new host.
2. If no other participants remain, `hostId` becomes `null` and the room is orphaned.
3. The new host's ID is written to `hostId` immediately on leave/disconnect.
